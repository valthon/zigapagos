# allocator-allowlist.txt — NO_SLOP.md §2.2a
#
# Every test site that wraps `std.testing.allocator` (or a local alias bound to
# it, the spelling this repo uses most) in an `ArenaAllocator`. Wrapping turns
# Zig's leak detector OFF for that test, so each file needs a reason.
#
# Format — TAB-separated, three columns:
#
#     <path>	<count>	<one-line justification>
#
# The gate (scripts/check-allocator-contracts.sh) fails when a file's count goes
# UP or when a file that is not listed here has any site at all. It never fails
# on a count going DOWN — deleting one of these is always an improvement; run
# `scripts/check-allocator-contracts.sh --update` to record the new number.
#
# HOW TO ADD A ROW: state WHY the code under test cannot be exercised with the
# raw testing allocator — i.e. why it is genuinely NO_SLOP contract 4
# (arena-scoped: an interlinked graph the caller reclaims by dropping the
# arena). "It was already written that way" and "adding defers is tedious" are
# NOT justifications, and neither is "the test passes".
#
# The counts below are the whole inventory — sum them for the total rather than
# quoting a number that rots. `--list` prints the live one.
#
# STATUS. Every remaining row has been audited against the three-part contract-4
# bar. Most of them call an API that takes `RenderArena`
# (src/islands/render_arena.zig) — with TWO exceptions, each noted on its own
# row: src/cli/migrate_detect.zig is its own test-module root, and Zig 0.16
# forbids an import escaping a module's directory, so it cannot reach the type
# without a build.zig change; src/cli/dev_lockfile.zig's read() is a leaky-JSON
# parse but is deliberately NOT a RenderArena consumer, because RenderArena is
# documented (render_arena.zig) as scoped to a page render pass, and a CLI
# control verb's lockfile read runs outside any render pass — reaching for
# RenderArena there would be a lifetime lie, not a convenience. There are no
# GRANDFATHERED rows left; do not add one.
# `RenderArena.forTest(std.testing.allocator)` is how a test satisfies an
# arena-scoped signature while KEEPING leak detection — reach for it first, and
# only fall back to a row here when the code under test genuinely cannot run on
# a GPA (a *Leaky parse graph with no `deinit`).
#
# A row is NOT the only way off this list, and swapping the arena for another
# non-detecting allocator (a stack FixedBufferAllocator, say) is not a fix: it
# hides the site from the scanner without restoring any detection. Either the
# code under test becomes contract 1/2/3, or it keeps its row.
#

src/cli/dev_lockfile.zig	1	JUSTIFIED contract 4: RenderArena (src/islands/render_arena.zig) is documented as scoped to a page render pass, and dev_lockfile.read() is called from a CLI control verb (dev stop|status|logs) that runs entirely outside any render pass — taking a RenderArena there would misrepresent the lifetime, so read() takes a plain Allocator by design, not oversight. It still parses dev.json via std.json.parseFromSliceLeaky and returns a LockFile whose string fields borrow that leaky-parsed memory (no deinit, same shape as manifest.zig's parse()), so the test wraps std.testing.allocator in a local arena to stay leak-clean. One of two exceptions (with migrate_detect.zig) to "every contract-4 row takes a RenderArena" — see STATUS above.
