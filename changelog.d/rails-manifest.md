### Added

- `zigapagos migrate` on a Rails source now emits a versioned, machine-readable manifest (`zigapagos.rails-presentation/1`) alongside `MIGRATION.md` — the deliverable Stage 3's route classifications, Stage 4's asset/integration/blocker inventory, and the template graph all previously existed only as prose in the report. It carries `source` (framework, Rails version + evidence, and the structural `root_evidence` that drove detection), `discovery` (route recovery mode, Ruby availability), every recovered `routes[]` entry (verb, path, controller/action, source location, origin, confidence, classification, candidate zigapagos shapes, resolved templates and layout), the route-reachable `templates[]` catalog (engine, kind, render targets, Stimulus controllers, mounted component roots), `assets[]` (source, public URL, pipeline, and whether that URL is statically derivable), `integrations[]` (detected gems/npm packages with their resolved versions), and every `blockers[]` entry (code, severity, integrity, source location, message, and the one route it names when it is route-scoped). The manifest is written beside the report, named from the report's own `-o` path with its extension replaced (`MIGRATION.md` → `MIGRATION.manifest.json` by default), and, like the report, is regenerated in place on every run rather than versioned as `.new*`.
- The manifest's JSON Schema (`contract/rails-presentation.v1.schema.json`) is generated FROM the emitter's own Zig types rather than hand-maintained, so a field can never drift out of sync with what actually gets written. `zig build rails-schema` regenerates it; `zig build rails-check` (now part of CI's build-test job) fails the build if the committed schema is stale.
- `zigapagos migrate --strict`: exits non-zero if the manifest records *any* blocker, regardless of severity — useful for an agent loop or a CI gate that wants a clean Rails discovery or none. `--strict` changes only the process exit code; the report and manifest it writes are byte-identical to a plain run on the same source tree. Rejected outright for non-Rails sources, which have no blocker concept to gate on.

### Known limitations

- The manifest is discovery output: it records what discovery established about the Rails app, and it does not change when the converter improves. The conversion added later in this release reads it and writes a second, separately-versioned artifact (`MIGRATION.handoff.json`) rather than amending it — so a route's `classification` here and its handoff `status` there are different claims, and may disagree.
