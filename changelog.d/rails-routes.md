### Added

- `zigapagos migrate` on a Rails source now recovers a route table from `config/routes.rb` and adds it to `MIGRATION.md` as a `## Routes` section. Recovery is **static AST parsing** (a Ruby sidecar walks `config/routes.rb` with Prism — the same technique Stage 1's inventory used for the presentation layer, extended into the router): the app is never booted and no gem is required. `root`, `resources`/`resource` (including `only:`/`except:`, `member`, `collection`, bare nested routes, and `concern`/`concerns`), `namespace`, `scope`, `get`/`post`/`put`/`patch`/`delete`, and `devise_scope` all expand to concrete routes. Every route records how confident the parser is: one it can vouch for renders plainly (`` - `GET /posts` → `posts#index` ``); one recovered from a construct the parser can see the shape of but not the activation of (a route inside `if`/`unless`/`case`) renders with a visible `— **uncertain**` marker instead of being asserted as fact.
- What the parser cannot resolve at all — a dynamic path segment, an engine mount (`mount Sidekiq::Web => "/sidekiq"`), a loop-generated route, an app-defined custom router, gem-generated routes (`devise_for`), or an externally-drawn file — is never guessed at or silently dropped. Each becomes a coded `RAILS_ROUTE_*` blocker in `## Blockers`, naming the source line and what could not be evaluated.
- `scripts/rails-route-calibrate.sh`: a developer-only tool (never run by CI, and no in-repo fixture depends on it) that fetches a corpus of real-world `config/routes.rb` files into a temp directory and reports the parser's recall/precision against a genuine `ActionDispatch::Routing::RouteSet` expansion, when `actionpack`/`activesupport` are installed. It degrades to a clear message — never a hard failure — when the network or those gems are unavailable, and it never writes into the repository: most of a realistic corpus (mastodon, discourse, canvas-lms, redmine, openproject, diaspora) is GPL/AGPL, and this repository is MIT, which is also why the in-repo fixture (`tests/migrate/rails-sample/config/routes.rb`) is synthetic rather than lifted from a real app.

### Known limitations

- Route recovery is **static AST parsing only**. The schema's `actiondispatch` mode (booting the target app and asking a real `RouteSet`) and `routes_import` mode (consuming a JSON dump produced by `rails routes`) are declared but not implemented — `static_ast` is the only mode Stage 2 ships, and it is the one designed to work on an app that cannot boot at all.
- Recovered routes are not yet classified. Whether a route serves static content, an island, an SPA shell, a redirect, or genuine backend logic that has no Zigapagos equivalent is Stage 3's job; Stage 2 only answers "what routes exist and how sure are we."
