### Added

- **`zigapagos migrate <rails-app> --from rails --target DIR` now converts.** Every route whose whole template graph has a defined conversion becomes a `content/<url>/index.smd` page plus the `.shtml` layouts it extends; deterministic assets are copied under `assets/` (excluding `public/assets/**`, the pipeline's compiled output, whose every file is a digested duplicate of an `app/assets/` source the conversion already copies from the source side; an asset helper naming an ABSOLUTE URL — `image_tag "https://cdn.example.com/x.png"`, or the protocol-relative `//cdn…` — is copied through into the markup verbatim and raises no finding, because the resource is on another host and there is no local file for it to be missing); and a `zigapagos.ziggy`, a `build.sh`, a `.gitignore` and the two agent files are written, so the emitted directory is a project the target's own `build.sh` releases. (One edit is needed first if any answer was `spa`: the generated `package.json` points `@z/runtime` at a `file:TODO-SET-RUNTIME-PATH` placeholder unless the `migrate` run was given `--runtime-path`.) Rails URLs map to a directory index (`/` → `content/index.smd`, `/about` → `content/about/index.smd`) so `/posts` and `/posts/new` cannot collide on a file-versus-directory name. The view body goes into the `.shtml` rather than the `.smd` because SuperMD forbids raw HTML; the `.smd` carries `.title` (from `content_for :title`, else the first `<h1>`, else `"<controller> <action>"`, else the path), `.layout`, and a `.custom.rails` provenance block naming the route, controller, action and source template.
- `DIR/MIGRATION.handoff.json`, schema `zigapagos.rails-handoff/1` — a second versioned artifact recording what each route *became*: `status` (`migrated`/`open`/`blocked`/`retained`/`backend`/`redirect`), the target-relative `artifacts` it produced, the finding ids it left open, the operator decision that settled it, and a `note`. Its JSON Schema (`contract/rails-handoff.v1.schema.json`) is generated from the emitter's own Zig types under the same `rails-check` gate as the discovery manifest, and every list it emits is sorted under a total order whose tiebreaks compare content rather than the producer's row order — so re-running the loop cannot move bytes.
- `MIGRATION.decisions.json` (schema `zigapagos.rails-decisions/1`, or `--decisions FILE`): the operator's answers. One `{id, choice, rationale}` per finding, where `choice` must be one of that finding's own `choices` and `rationale` is required and non-blank — the file outlives the run, and an unexplained `blocked` is a decision nobody can revisit. A decision whose id matches no finding in this run is reported as a `RAILS_DECISION_STALE` blocker rather than rejected: finding ids derive from the template's own text and location, so *fixing* the template you were asked about is exactly what makes your answer's id disappear, and failing there would punish the remedy.
- Exit code **3**: everything was written and read correctly, and at least one user-facing route is still unanswered. Distinct from the existing exit 1 (an integrity blocker, or `--strict` with any blocker) on purpose — a decide-and-re-run loop has to tell "keep going, here are the questions" apart from "this run is broken, stop". `complete` is true iff every GET/HEAD route is `migrated` or `redirect`, or `retained`/`blocked` **with a decision** (`backend` was on that list when this fragment was written; `rails-backend.md` in this same release narrows it to `backend` **with an endpoint or a decision**, and the sentence is corrected here rather than shipped beside its own successor); a route with no row at all counts as unanswered, so a conversion that silently skipped a route cannot report itself complete. `retained` and `blocked` are the two statuses only an operator can produce, and both mean the target serves nothing at that URL — so neither counts without the decision that produced it.
- Eight finding codes are emitted for the first time — `RAILS_ASSET_TRANSFORM`, `RAILS_ROUTE_DYNAMIC_SEGMENT`, `RAILS_REDIRECT_HOST_CONFIG`, `RAILS_NO_TEMPLATE`, `RAILS_BACKEND_ENDPOINT`, `RAILS_TURBO_FRAME`, `RAILS_TURBO_STREAM`, `RAILS_TEMPLATE_ENGINE_UNSUPPORTED` — plus `RAILS_COMPONENT_ROOT`, which is new. The form/Turbo/component ones exist so that a region the converter cannot finish is at least *acknowledgeable*: without them a route whose only blemish was a form could never be closed by any answer at all, because the placeholder that form converts to carries no finding id. `RAILS_TEMPLATE_ENGINE_UNSUPPORTED` is the same hole in the one place it had not been closed, and is now the only code that is **both a blocker and a finding**: the blocker explains the engine in the report and counts under `--strict`, and the finding (`choices: [retain, blocked]`, `line: null`, `loc: "engine"` — nothing ever parsed the file) is the id an operator answers. It does not make a Haml route convertible; `migrated` is not a choice anywhere, so such a route can only be acknowledged — and a route whose *layout* is the Haml file carries that layout's id too, so one answer settles every route under it rather than one answer per page. `RAILS_NO_TEMPLATE` closes the last instance of the same hole: a GET route whose controller action resolves no view at all (`def other; render :about; end` with no `other.html.erb`) used to report a sentence with no id behind it, which made `complete` unreachable for the whole app. Like the other two route-scoped codes it is keyed on the `routes.rb` declaration line, and it offers `retain`/`blocked` only — there is no template, so no answer produces a page. Answering `RAILS_ROUTE_DYNAMIC_SEGMENT` with `spa` scaffolds one `.spa.tsx` per first path segment (`/posts/:id` and `/posts/:id/edit` are two routes of one SPA, not two SPAs) and adds the matching `--spa=` to `build.sh`.
- `docs/migration/rails-to-zigapagos.md` gains the conversion half: what `--target` writes, the fragment-by-fragment conversion table, the three markers the converter leaves in the emitted HTML, the decisions file and its validation errors, the handoff's fields and completion rule, and the re-run loop. Mirrored byte-for-byte into `skills/zigapagos-rails-migration/references/` as `tests/skills/sync.sh` requires, and `SKILL.md`'s procedure now runs the loop rather than stopping at discovery.

### Changed

- **Rails' `--target` no longer writes only the discovery artifacts.** The `rails-target.md` fragment earlier in this same release said it wrote `MIGRATION.md` and `MIGRATION.manifest.json` and nothing else, and that its narrowness was deliberate because Rails discovery converts nothing; that fragment has been corrected alongside this one rather than left to publish a contradiction. The manifest itself is unchanged and still byte-identical between a `-o` run and a `--target` run over the same app — it is discovery's verdict and knows nothing about the conversion. What differs is `MIGRATION.md`, which gains a `## Handoff` section.
- A route's handoff `status` and its manifest `classification` answer different questions and may disagree; where they do, the conversion wins. In this repository's own fixture every `pages` route classifies `unresolved` because a coarse substring scan sees `csrf_meta_tags` in their layout, and `GET /about` still reports `migrated` — that helper's conversion is "drop it, and say so in a comment". The reverse also holds: a `content` route whose view holds one unknown helper is `open`. A consumer asking "did this route migrate" must read `status`.
- **An acknowledged route writes no page and no view file.** A `retain` answer means the page stays on Rails, so the migrated tree must not answer that URL; a `blocked` answer means it does not ship. Emitting the page anyway made `blocked` a relabelling — the built site served a blank `<main>` for a route the handoff called blocked, which is worse than a 404 because it looks deliberate. The answered run therefore produces a *smaller* tree than the unanswered one, and `zigapagos doctor` reports a `dangling-internal-link` warning for each surviving link into such a route: the honest report of a partial migration. Shared layouts under `layouts/templates/` are unaffected — a layout is written once per layout rather than per route, so one can outlive every page that extended it.

### Known limitations

- At this point islands were not produced for the Turbo/component family. `rails-interactivity.md` later adds portable Stimulus, Turbo-frame, React, and record-backed data islands and closes #184; Turbo Streams and Vue roots remain `retain`/`blocked` rather than approximated. `rails-backend.md` separately binds forms, mutating links, and the auth journey.
- **One shape cannot be closed by any decision:** a `rails:unmapped` region on a route that raises no finding at all — the placeholder carries no id by construction, so a decisions file has nothing to name. It is emitted from four places in the converter -- an unbound template local; a `render` target that is not a literal / resolves nowhere / is cyclic / names an unparseable template; a `content_for :title` whose BODY is not a single literal (a computed block *name* never becomes a `content_for` fragment at all, since the classifier requires a literal first argument -- it raises `RAILS_HELPER_UNKNOWN`); and a backstop for a node whose finding id lookup missed, which in practice catches a route helper called with the wrong arity, such as `post_path` for a `/posts/:id` route, where the route NAME resolved so no `RAILS_ROUTE_HELPER_UNKNOWN` was raised. The case that bites is one of them landing in a view that raises nothing else. None of these is owned by a later stage, so the route's `note` reports `<kind>: converter gap (see #181)` rather than `deferred to Stage 3`/`Stage 4`, which are reserved for the form and Turbo/component families a later stage really does own. The honest fix is in the converter (inline or drop the construct), not in the decision plumbing. Every other unfinished shape is answerable, including a parse error, an unsupported engine, an unsupported engine in the *layout*, and an action with no template at all.
- At this point a scaffolded SPA had no `spa.head`; `rails-interactivity.md` later recovers deterministic stylesheet links from the Rails layout and closes #180.
- `parity[]` was declared empty at this point; `rails-parity.md` in this same release now fills it with typed replay evidence. (This bullet also said `redirects[].to` and `routes[].endpoint` were always `null`; `rails-backend.md` fills both, and the sentence is corrected here rather than shipped alongside its own refutation.)
- The emitted `zigapagos.ziggy` carries `host_url = "https://example.com"`. Rails' own config knows the production host, but this stage does not read it, and inventing one would be worse than an obvious stand-in.
