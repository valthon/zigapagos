### Added

- `zigapagos migrate` now detects Rails projects (auto-detected via `config/application.rb` or `config/routes.rb` + `app/views` + a `rails` gem, or selected with `--from rails`) and writes a `MIGRATION.md` presentation inventory: view/layout/partial/mailer-view/controller/helper/Stimulus-controller/JS-entrypoint/JS-module/asset counts, detected asset-pipeline and frontend integrations (Propshaft, Sprockets, importmap, jsbundling/cssbundling, Vite, Turbo, Stimulus), and blockers. This is **detection and inventory only** — Stage 1 converts nothing. Route discovery, a machine-readable manifest, and `--target`/`--copy-assets` assembly are not implemented yet; both flags are rejected outright for Rails sources rather than silently no-oping. `--from rails` against a directory that fails Rails detection is a fatal error, not a confident empty report.
- Inventory and read failures now surface as blockers instead of being silently swallowed: an unreadable or truncated `app/`/`public/` walk, an unreadable Gemfile or package.json, and a malformed package.json all get a stable `RAILS_*` blocker code in the `## Blockers` section, alongside the existing unsupported-template-engine (Haml, Slim) findings. A blocker whose failure means the inventory itself can't be trusted (an unreadable/truncated walk root, an unreadable Gemfile/package.json) makes `zigapagos migrate` exit non-zero after writing the report; an expected finding like an unsupported template engine or a malformed-but-present package.json does not.
- `app/javascript/` classification is more precise: only a top-level file directly under `app/javascript/` counts as a JS entrypoint now (`| JS entrypoints |`); everything else under it (shared components, libraries, non-Stimulus files inside `controllers/`) is counted separately as a JS module (`| JS modules |`) instead of being miscounted as an entrypoint. Stimulus controller detection now matches any script extension (`.js`, `.mjs`, `.ts`, `.jsx`, `.tsx`) at any depth under `app/javascript/controllers/`, not just a top-level `*_controller.js`.
- Gemfile gem detection (`gem "x"`) now also accepts `gem 'x'`, `gem("x")`, `gem( "x" )`, and a tab in place of the space, so a project using the parenthesized call style is no longer misdetected as not using Rails or a given integration gem.
- `package.json` dependency detection is now a real JSON parse scoped to the `dependencies`/`devDependencies` objects, rather than a raw substring scan — a differently-formatted (but valid) `package.json`, or an unrelated same-named key elsewhere in the file, no longer produces a wrong result.
